# H2 baseline review

## Recommendation
Primary comparison: freeze a bank of full LIME surrogates h_E (not a bank of perturbations). Each score uses permitted deployment information; final loss uses an independent held-out probe set shared only by the evaluator for paired comparisons. Compare (1) direct independently measured functional-fidelity score with (2) a learned predictor of absolute functional loss. Feed both rankings through the existing A3 LTT reference, with identical examples, score orientation, calibration split, threshold grid, and evaluation. This tests whether learning the loss-ranking signal helps; it does not confuse a quality score with observed loss.

Do not compare different perturbation banks or reuse training/evaluation probes. Preserve the full local surrogate (intercept plus coefficients and the exact feature transform). Direct score uses its own fixed-budget score probes. Learned score is fitted on disjoint development units/labels and never reads calibration/final loss probes at prediction time. Calibration loss and final evaluation loss each use separate streams; the final evaluator may share a held-out probe realization across score policies for a paired comparison, never with either scorer. Record the surrogate representation and probability scale.

Bayes is a separate secondary arm with native h_B bank and its own independent evaluation set E_B. Compare direct probe score, learned score, and a posterior-derived score on the same E_B. Never use h_B uncertainty to score the LIME bank. In the pinned source Bayesian regression stores s_2 as score; it is a residual-variance proxy, not absolute functional loss and not the paper’s error-density-at-zero. It may be tested as a proxy ranking only, evaluated independently.

## Guarantee and controller interpretation
LTT controls population risk conditional on acceptance, under fixed-policy/IID/calibration assumptions. Its outer high-probability event is over calibration samples, not conditioning on a realized accepted count. Accepted-count conditioning is only one possible existing testing construction; FWER controls erroneous risk-null rejections across the family, not per-input/subgroup/shift risk. Do not describe a native selector fallback as an acceptance filter. The existing conditional-on-accepted-count test is a strong future A5 validity/power audit option, not a new controller. Prefer direct-probe versus learned-absolute-loss ranking under the same LTT reference; avoid a weak-null strawman.
