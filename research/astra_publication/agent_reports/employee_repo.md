## Follow-up: implementation trace and additional completed compact runs (round2 commit 176e8b1cd78d9af84aaf069fab0f683682885c58)

### Calibration implementations and leakage distinction
Inspected src/experiments/final_calibration.py, src/experiments/manuscript_calibration.py, src/experiments/manuscript_model_benchmark.py, src/models/canonical_models.py (benchmark entrypoints/contracts), and relevant manuscript passages at this immutable SHA.

- The older final_calibration.py is a separate exploratory final-candidate workflow: outer StratifiedKFold (default 10); each outer-train split is divided by stratified train_test_split (80/20); one pipeline is fitted on inner-development data; sigmoid/isotonic are fitted using calibration-split predictions and labels and evaluated on outer-test predictions. Thus outer outcomes do not fit calibrators. But calibration-method comparisons are evaluated across the same outer test folds and write_interpretation selects “best” methods by observed mean ECE/log loss/Brier (and a rank composite); that is **inner-selection leakage** if those selected metrics/method are then presented as an unbiased winning-method estimate. It is not outer-test leakage into model/calibrator fitting. No evidence this exploratory script produced the canonical manuscript result; its outputs are reports/calibration/final_candidates and must not be conflated with Phase 2b.
- Canonical manuscript_calibration.py explicitly fixes sigmoid in protocol, consumes persisted shared 10×5 fold artifacts and per-outer-fold selected XGBoost model identities; checks selected candidate equals benchmark’s exact outer model and validates persisted probability replay. For each outer fold, it refits that selected parameterization on each of five inner development partitions, preprocesses there, predicts each held-out inner fold exactly once, fits per-class one-vs-rest Platt sigmoid on pooled outer-training cross-fitted probabilities, and applies it to the exact persisted outer benchmark-model probabilities. Outer-test outcomes are only evaluated, not used in tuning, calibrator fit, method selection, or threshold selection. This avoids both outer leakage and a calibration/model identity mismatch. Tuning the parameters on inner folds and fitting calibrator on cross-fit probabilities from those same inner OOF partitions is standard nested cross-fitting; training-fold predictions are held out from each refit.
- Source enforces matching outer candidate index and pipeline feature/parameter lineage; checks fold partition identity, class labels, exact once OOF membership, probability replay, and hashes. Shared split and model benchmark contracts declare nested folds, common fold assignment, a 0.001 macro-F1 tie pool then QWK/candidate-index tie-break; candidate search validates exact model families/candidate counts and failure policy. Manuscript states preprocessing is refit inside current inner-development or outer-training partition (median impute/scale numeric; most-frequent impute/one-hot categorical). Model construction uses pipeline builder. These source-level checks support method correctness; no tests or experiment executions were performed in this follow-up.

### Sigmoid normalization and Eq. 10
The canonical implementation is explicitly one-vs-rest Platt logistic calibration of each class column followed by row-wise renormalization: apply sigmoid to each independent class logit, then divide each resulting class score by that row’s sum; this is not a multiclass softmax and the three independent sigmoid outputs do not in general sum to one before normalization. Raw persisted probabilities are accepted without silently renormalizing (float32 simplex tolerance); calibrated values are normalized and simplex-validated. manuscript_calibration.py protocol names the algorithm one_vs_rest_platt_logit_then_row_renormalize. Manuscript text at main.tex line 198 (main.md line 139) says “Outputs are renormalized” but does not provide a displayed Eq. 10 in the inspected tracked manuscript. Therefore if an Eq. 10 elsewhere writes sigmoid outputs directly as final class probabilities without the denominator/row-normalization, it mismatches the code and yields a non-simplex vector; report/calibration numbers correspond to renormalized probabilities. I could not confirm the cited Eq. 10 within the inspected manuscript file.
